1. Executive Summary & Problem Statement

1.1 Executive Summary

Digital identity verification is a fundamental pillar of modern banking (KYC), immigration, government services, and online platforms. With the widespread accessibility of generative image tools, photo-editing software, and synthetic identity fraud, organizations face an unprecedented volume of forged and counterfeit identity documents.

This project delivers an intelligent, end-to-end, multi-stage identity verification platform capable of screening Indian identity cards—specifically Aadhaar Card, PAN Card, Passport, and Voter ID Card. Unlike conventional verification systems that blindly execute a single binary classification model, our architecture implements a Two-Stage Validation Pipeline that guarantees document-type identity before assessing authenticity.

1.2 The "Cross-Type False Confidence" Vulnerability

Earlier generation computer vision classifiers suffer from a critical algorithmic flaw known as Cross-Type Confidence Inflation. When separate binary classifiers are trained exclusively on one document type (e.g. an Aadhaar model trained solely on original vs. fake Aadhaar images):

The Problem: When a user selects "Aadhaar Card" and uploads a completely different document (such as a Passport or Voter ID), the Aadhaar binary model—never having seen a Passport during training—still forces a softmax probability distribution over [ORIGINAL, FAKE]. This results in absurd verdicts like "Aadhaar ORIGINAL 99.8%" on a clear Passport image.

Furthermore, selecting the highest score among all binary models to infer the document type is equally flawed: because each binary model outputs ~99-100% confidence for almost any input, model confidence cannot be used for type identification.

1.3 Solution Overview: Decoupled Two-Stage Architecture

To permanently resolve this vulnerability, our system strictly enforces a decoupled architecture:

  • Stage 1 (Document Type Validation): Evaluates three independent signals (Multilingual OCR, Dedicated 5-Class Doctype Classifier, and AI Vision LLM) under a strict priority hierarchy to establish what the document is. Per-type authenticity models are strictly prohibited from participating in Stage 1.
  • Stage 2 (Authenticity & Quality Verification): Only executes once Stage 1 confirms that the uploaded document matches the selected document type. If a mismatch or unrecognized document is detected, Stage 2 scores are completely suppressed and hidden.

3. Stage 1: Document Type Detection Engine

Stage 1 acts as an impenetrable gatekeeper. It evaluates the uploaded document against three independent signals and arbitrates through a deterministic 5-rule decision hierarchy.

3.1 Signal 1A: Enhanced Multilingual OCR Engine

Optical Character Recognition serves as the most definitive proof of document identity. Real-world documents are often photographed in suboptimal lighting, low resolutions, or rotated orientations. To overcome this, our system executes a 4-step image enhancement pipeline:

  1. Long-Edge Upscaling: Images with dimensions below 1600px are bilinearly upscaled to a target long edge of at least 1600px (capped at 2200px) to maximize OCR character glyph recognition.
  2. Luminance & Gamma Brightening: The average luminance $L_{\text{avg}} = \frac{1}{N}\sum (0.299R + 0.587G + 0.114B)$ is computed. If $L_{\text{avg}} < 80$, a non-linear gamma expansion ($\gamma = 0.55$) is applied to boost dark shadows without blowing out highlights: $$I_{\text{out}} = 255 \times \left(\frac{I_{\text{in}}}{255}\right)^\gamma$$
  3. Adaptive Contrast Stretching: A piecewise contrast enhancement expands the dynamic range around midtones.
  4. Four-Angle Orientation Sweep: The engine tests $0^\circ, 90^\circ, 180^\circ,$ and $270^\circ$. If a strong identifier is detected at any angle, the sweep terminates early to optimize latency.

3.2 Signal 1B: Dedicated Document Type Classifier (`./model-doctype/`)

When OCR text is unreadable or blurred, the system relies on a dedicated 5-class MobileNetV2 neural network. Trained across five distinct classes (aadhaar, pan, passport, voter, other), this model evaluates macro-level visual features: layout geometry, color palettes, photo positioning, and structural emblems.

  • Letterbox Preprocessing: Maintains image aspect ratio by embedding the document inside a square $224 \times 224$ canvas with neutral gray padding (#808080), preventing geometric distortion.
  • Rotation Invariance: Evaluates the image across four $90^\circ$ rotations and averages the softmax probability vectors: $$\bar{P}(c) = \frac{1}{4} \sum_{\theta \in \{0, 90, 180, 270\}} P_\theta(c)$$

3.3 Signal 1C: Multimodal AI Vision LLM (Gemini Vision)

For complex edge cases (e.g. heavily damaged or obscured documents), the system calls the backend endpoint /api/verify-doc-type. The multimodal model inspects layout symmetry, governmental emblems, photo borders, and security watermarks, returning a structured JSON response containing: 

{
  "type": "aadhaar" | "pan" | "passport" | "voter" | "other",
  "confidence": 0.0 - 1.0,
  "reason": "Clear presence of UIDAI emblem and 12-digit number format.",
  "fake_signals": ["screen_moire_detected", "font_inconsistency"]
}

3.4 Priority Decision Rules (Rules 1 to 5)

  1. Rule 1 (Definitive OCR Match): If OCR yields strong identifiers for exactly ONE document type, that type is immediately selected with 99% confidence. All subsequent signals are bypassed.
  2. Rule 2 (Multiple OCR Matches): If multiple types return strong keywords, the type with the highest score is chosen, but flagged as Low Certainty (82% confidence), offering user confirmation buttons.
  3. Rule 3 (Dedicated Doctype Classifier): If OCR yields no strong hits, the neural classifier is inspected. If its top probability is $\ge 0.85$ and no competing rival class exceeds $0.30$, its verdict is accepted.
  4. Rule 4 (AI Vision LLM): If the local classifier is ambiguous or missing, the Vision LLM is queried. If confidence $\ge 0.75$, its prediction is adopted.
  5. Rule 5 (Fallback / Unrecognized): If all signals fail or point to other, the system triggers the Unrecognized Document shield.

4. Stage 2: Authenticity Screening & Forensic Analysis

Stage 2 is executed exclusively when Stage 1 has confirmed that the uploaded document matches the user's selected category. It combines deep neural feature extraction with client-side image forensics.

4.1 Strict Isolation Policy

Security Guarantee: Whenever Stage 1 detects a document-type mismatch or an unrecognized image, the entire Stage 2 results panel (including the ORIGINAL/FAKE progress bars and confidence percentages) is completely hidden. The system replaces it with the message: Not verified - document type unconfirmed.

Algorithmic Details:

  • Laplacian Variance Blur Detection: Convolves a $3 \times 3$ discrete Laplacian operator over the grayscale image to measure high-frequency edge energy. A variance below 70.0 indicates camera motion blur or out-of-focus capture: $$\nabla^2 f = \frac{\partial^2 f}{\partial x^2} + \frac{\partial^2 f}{\partial y^2}$$
  • Exposure & Luminance Analysis: Average pixel brightness must fall within 35 to 225. Values below 35 represent severe underexposure; values above 225 represent overexposure and washed-out text.
  • Screen Moiré / Recapture Detection: Computes high-frequency diagonal periodic pixel intensity variances. Documents captured off an LCD/OLED monitor exhibit characteristic moiré interference fringes.

5.2 Data Preprocessing & Deduplication

  1. Deduplication via Hash: Every input file is hashed using SHA-256 over raw pixel bytes to eliminate redundant downloads and augmentations.
  2. 80 / 10 / 10 Split: Data is split by file into 80% Training, 10% Validation, and 10% Test partitions. Stratification guarantees that minority classes (such as Aadhaar) have samples represented across all three splits.
  3. Aadhaar Minority Class Balancing: Because Aadhaar has a smaller base sample count (9 images), heavy offline and online data augmentation is applied:
    • Random rotations: $\pm 25^\circ$
    • Brightness jitter: $0.7\times$ to $1.3\times$
    • Random zoom: $0.8\times$ to $1.2\times$
    • Color jitter & slight perspective shear
    Furthermore, balanced class weights are injected into the loss function: $$W_c = \frac{N_{\text{total}}}{C \times N_c}$$ ensuring that the gradient update from each Aadhaar image is proportional to its representation.

5.3 Neural Architecture & Web Export

The model utilizes MobileNetV2 ($\alpha = 0.35$) with ImageNet transfer learning weights. The feature extractor produces a 1280-dimensional embedding vector, followed by: 

Sequential [
  MobileNetV2 Base (alpha=0.35, input=[224, 224, 3]) -> 1280-dim feature vector
  Dense Layer 1 (units=100, activation='relu', use_bias=true)
  Dense Layer 2 (units=5, activation='softmax', use_bias=false)

The trained model is serialized into standard Teachable Machine / TensorFlow.js format:

  • model.json: Contains full model topology and weights manifest.
  • weights.bin: Contiguous float32 little-endian binary weights buffer.
  • metadata.json: Contains {"modelName":"tm-my-image-model","labels":["aadhaar","pan","passport","voter","other"],"imageSize":224}.
